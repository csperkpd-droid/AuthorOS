# Decision log

Short architecture decision records. Each entry: the decision, why, and what
was rejected. Add new entries at the bottom; supersede old ones rather than
editing them.

Status key: **Accepted** · **Superseded by #n** · **Proposed**

---

### 1. Modular monolith on Next.js — Accepted (M0)

One Next.js app with domain modules (`src/modules/*`) and lint-enforced
boundaries. **Why:** one team, one heavily connected database; splitting
services would cut exactly the relationships the product is about.
**Rejected:** microservices (operational cost, no benefit at this scale); a
separate Node API server (duplicates auth and types for no gain now;
services are framework-free, so an API can wrap them later).

### 2. Next.js 16 App Router: Server Actions + Data Access Layer — Accepted (M0)

Reads in Server Components, writes via Server Actions, authorization in a DAL
(`requireAuthorContext`) per Next.js 16 guidance. `proxy.ts` (formerly
middleware) only does optimistic cookie redirects. **Rejected:** auth checks
in layouts (they don't re-run on navigation); a REST/tRPC layer for internal
calls (unneeded indirection).

### 3. Neon Postgres via the Vercel Marketplace — Accepted (M0)

**Why it fits best:** a native Vercel integration (environment variables are
provisioned automatically); a **database branch per preview deployment**, so
migrations run safely on every preview; standard Postgres (no lock-in, works
with plain `pg`); pooled and direct URLs for runtime and migrations;
scale-to-zero keeps cost near zero during development.
**Rejected:** Supabase (brings its own auth, storage and APIs that duplicate
Auth.js and our service layer); Prisma Postgres (couples the database host
to the ORM vendor); self-hosted (operational burden).

### 4. Prisma ORM 7.10 (stable), node-postgres driver adapter — Accepted (M0)

Prisma 7's `prisma-client` generator outputs to `src/generated/prisma`
(gitignored, generated on `postinstall`); the database URL lives in
`prisma.config.ts`. **Why 7.10:** latest stable. Prisma 8 is still a release
candidate and is not used for a production foundation; we upgrade once it is
stable. **Why `@prisma/adapter-pg`:** works identically against local
Postgres, CI and Neon's pooled endpoint; `@prisma/adapter-neon` is a drop-in
swap if we ever need edge runtimes.

### 5. Auth.js v5 (pinned beta) with database sessions — Accepted (M0)

`next-auth@5.0.0-beta.32`, pinned exactly. v5 is the only line that supports
Next.js 16 App Router idioms. Its "beta" label is long-standing; the API is
stable in practice. **Risk:** upgrades between betas may need small changes,
so the version is pinned and upgrades are deliberate.
**Database sessions over JWT:** server-side revocation, a future "sign out
other devices" option, and session rows usable for collaboration. The cost
(one indexed query per request, memoized) is negligible.

### 6. Magic links via Resend; local dev outbox — Accepted (M0)

The email provider uses id `email` (not `resend`), so callback URLs stay the
same if the email service changes. Without `AUTH_RESEND_KEY`, links are
printed and written to `.dev-mail/outbox.jsonl`, which also lets end-to-end
tests sign in for real. The outbox refuses to run on Vercel.

### 7. Google accounts link to existing users by email — Accepted (M0)

`allowDangerousEmailAccountLinking` is enabled for Google only. Google
returns verified addresses and magic links prove ownership of the address,
so an author who signed up by email can later use Google (and the reverse)
without hitting `OAuthAccountNotLinked`.

### 8. Workspace tenancy from day one; single-author MVP — Accepted (M0)

All data hangs off `workspace_id`, not `user_id`. Each user gets one
personal workspace and the MVP shows no workspace UI. **Why now:** moving
from user-owned to workspace-owned data later means rewriting every query
and migrating every row; adding it now costs one table and one join.
Collaboration later becomes additive (members, invitations, role checks).

### 9. Pen names are first-class from day one — Accepted (M0)

A `pen_names` table exists in M0; each workspace gets a default pen name;
series, books and editions will reference one. **MVP scope:** one default
pen name, editable later; the database already allows many. **Rejected:**
storing an author name as a text field on books (multiple identities
would then need a migration and data cleanup).

### 10. UUIDv7 primary keys — Accepted (M0)

Time-ordered, so index inserts stay local; not guessable; safe in URLs;
generated by Prisma. **Rejected:** serial integers (enumerable, awkward to
merge); cuid2 (not native to Postgres types).

### 11. snake_case database names — Accepted (M0)

Models map to snake_case tables and columns, so hand-written SQL (search,
reports, CHECK constraints) is idiomatic Postgres. Auth.js OAuth token fields
keep the adapter's names.

### 12. Explicit foreign keys over polymorphic links — Accepted (M0)

Notes and tasks attach to entities via nullable FKs plus a CHECK constraint
(an "exclusive arc"), not `(entity_type, entity_id)`. **Why:** referential
integrity, cascades, type-safe joins. **Exception:** AI `suggestions` are
polymorphic because they are transient review records validated by the owning
service on accept.

### 13. Soft delete for creative content — Accepted (M0)

`deleted_at` on everything an author writes or plans; a Trash restores it.
Authors fear losing work more than they value a tidy database.

### 14. Fractional indexing for ordering — Accepted (planned for M1)

Text `position` keys let a drag-and-drop move update one row. **Rejected:**
integer positions (renumbering siblings on every move causes write
amplification and conflicts).

### 15. AI may only write `Suggestion` rows — Accepted (planned for v1.2)

The core product promise, enforced in code: the AI module has no write path
to creative tables; accepting a suggestion is a user action that records a
revision.

### 16. Migrations run during the Vercel build — Accepted (M0)

`vercel-build` runs `prisma migrate deploy && next build`. This is safe
because Neon gives each preview its own branch. Migrations must be
backward-compatible (expand, then contract).

### 17. TypeScript 5.9 — Accepted (M0)

TypeScript 7 is out, but `typescript-eslint` supports `< 6.1`. Revisit when
the lint toolchain supports TS 7.

### 18. Hand-written shadcn/ui-style primitives — Accepted (M0)

`components/ui` follows shadcn/ui conventions (cva, `cn`, CSS-variable
tokens), and `components.json` lets the shadcn CLI add more later. Only the
primitives in use are included.

### 19. A feature registry drives navigation — Accepted (M0)

`src/config/navigation.ts` lists every module with its availability
(available / planned milestone / later release). Sidebar, dashboard and
placeholder pages render from it, so adding a module is one entry.

### 20. Tests use a real database — Accepted (M0)

Integration tests run services against a migrated test database; no ORM
mocks. End-to-end tests perform the real magic-link sign-in. **Why:** the
riskiest code (tenancy scoping, constraints, concurrency) is only meaningful
against Postgres.
