# Spellbound Draft conventions

Read `docs/ARCHITECTURE.md` and `docs/DATABASE.md` before changing structure or schema.

**Where the rules live.** `docs/ARCHITECTURE.md` → **Architecture baseline** is the authoritative definition of the 29 invariants; this file is the implementation rules derived from it; `docs/DECISIONS.md` records why. If they ever disagree, the baseline wins and the others are corrected. Don't create other policy documents.

- **Architecture freeze:** new features fit the existing categories (object, relationship, assignment, view, representation, task, workflow, asset, integration, configuration, policy, automation, finding, event). If a capability fits none or would break an invariant, stop and ask for an architectural review instead of inventing a new pattern. No speculative abstractions: build a cross-cutting capability with its first real use.
- **Product rules:** AI never writes creative content (only `Suggestion` rows). Creative content uses soft delete and revisions.
- **Layers:** `src/app` routes are transport only. Business logic lives in `src/modules/<name>/service.ts`; services take `AuthorContext` first and scope every query by `ctx.workspaceId`.
- **Module boundaries:** import other modules only via `@/modules/<name>` (domain: services, schemas, labels) or `@/modules/<name>/ui` (components, Server Actions); enforced by ESLint. Routes and components never import `@/lib/db` or Prisma.
- **Story objects** get their id from `createStoryNode()` in the same transaction (see Story Graph in `docs/ARCHITECTURE.md`); the import is the one exception (it inserts nodes with the bundle's ids). Permanent deletion = deleting the node. Pen names are story nodes too.
- **Domains:** keep Story (what exists), Plan (what the author intends: structures, beats), Manuscript (the written words) and Publish (editions) separate. The registry area `planning` is the author's real-world planner (tasks, events, progress), not the story's Plan.
- **Story Object Registry:** every kind is defined once in `story-graph/kinds.ts` (with its adapter in `story-graph/adapters.ts`). Read kinds, capabilities and labels from it; never keep another list of kinds.
- **Connections:** flexible links between story objects use the `connections` module (kinds in `connections/registry.ts`); structural relationships stay explicit FKs. A new node kind needs: the enum value, a table with the two story-node triggers, a registry entry and adapter (TypeScript flags the rest), its visibility rule, its export/import columns; `tests/integration/story-graph-integrity.test.ts` must pass for it.
- **Dedicated relationships first:** a relationship the product relies on is its own table; Universal Connections only supplement. **Scene Participation** (a character's relationship to a scene: POV, Present, Mentioned; at most one POV per scene) is a dedicated relationship (DECISIONS 106, built in M11 as the `participation` module and `scene_participations`): a character is Present or Mentioned, and may also be the scene's point of view. Asking for a second POV is refused; changing the POV is its own explicit action (`setPointOfView`), never a side effect. Participation is the author's statement: never inferred from the text, never changes the text. Changes need edit rights on the manuscript and are kept in the scene's Story History. There is no `appears_in` connection kind any more; don't bring scene appearances back into Universal Connections.
- **Scene is the bridge, not a dumping ground:** systems attach to scenes through their own relationships (placements, participation, story time); don't add their columns to `scenes`.
- **Structure vs connections:** beat → scene placement is structural (`structure` module, `beat_scenes`), never a connection; scenes are never copied. Versioned content goes through the `history` module.
- **Identities:** characters, relationships and outlines belong to one pen name; never link across pen names (`sameIdentity()`). Notes and ideas are shared.
- **Change Impact:** changes that move, delete, detach or affect connected story data (pen-name moves, deleting forever, deleting a field or template, leaving a series, removing members, beats or parts) produce a report with `buildReport()` (`@/modules/impact`) and apply through `assertReviewed(report, token)`. Keep reports factual. Never move identity as a side effect of an edit; never detach or orphan silently.
- **Authorization, writes:** every service that changes data calls `assertCan(ctx, action, area)` (`@/server/policy`) as its first statement; `tests/integration/authorization.test.ts` enforces it. Changes go through these named Domain Actions, never generic CRUD.
- **Authorization, reads:** every service that returns author data calls `assertCanView(ctx, area, resource?)` first; pass the object (`{ kind, id }`) when reading one, so a refusal looks exactly like "not found". Paths from ids or queries to story objects go through the Story Graph funnel (`resolveNodes`, `searchNodes`, `viewableKinds`); never query another kind's table to bypass it. Workspace membership alone grants nothing. `tests/integration/read-authorization.test.ts` enforces it. Provenance or a link never grants access.
- **Author content safety:** long-form text gets history: documents through the `history` module (versions, checkpoints); other long-form fields through `recordFieldHistory()` in the same transaction as the edit. Metadata edits take an `EditGuard` (`lib/concurrency.ts`) and refuse stale forms. Editors keep the local draft first (a permanent safety layer, DECISIONS 101; never remove or bypass it because cloud autosave works) and never show "saved" for text only this device has. Device drafts are owned by one account (`DraftRef.owner` = `draftOwner(ctx)`), are never deleted by signing out, and are never shown to another account. Signing out works offline (the `authoros-signed-out` mark, finished by `/sign-out`); nothing may be sent for an account after it. A document schema change adds an upgrade step in `lib/doc-format.ts`.
- **History ≠ Provenance ≠ Validity ≠ Change Impact:** four separate capabilities; don't implement one through another. Validity uses exactly these states: Current, Potentially Stale, Conflicted, Invalid, Superseded, Unknown, Intentionally Excepted. Validity and findings are observations shown to the author, never automatic fixes or errors.
- **Change Impact levels:** Green = automatic factual propagation; Yellow = suggested consequences (report groups with `level: "suggested"`), applied only when accepted (`assertReviewed(report, token, accepted)`); Red = approval required.
- **AI:** AI writes only suggestions; the author approves; an authorized Domain Action applies the change and records its provenance. AI never gets its own database-write path.
- **Governance and classification:** governance (required reviews, safety rules) is separate from permission; no role, setting or automation may bypass it. Sensitivity, authority, permission, validity, provenance and truth are separate properties; authority is not truth.
- **Book ≠ Edition, Publication Boundary:** writing status belongs to the book and never says "Published"; publication belongs to editions. A manuscript change never silently changes a published edition.
- **Time:** Story Time (in the story) is separate from real-world planner time, publication dates and version timestamps; never store one in the other's fields. Story Time is built (M12, DECISIONS 109, `timeline` module): a scene is one point (`scene_story_times`) on its book's or series' timeline with timeline events, ordered by `lib/ordering` positions; labels are free-form and never parsed as dates; nothing is placed automatically or inferred from text; Story Time and reading order never change each other. A scene's story time needs manuscript edit rights, events story-bible rights. Moving a book into or out of a series is a Red review that lists its Story Time.
- **Assets ≠ Files; Search ≠ Query ≠ Reasoning:** an asset is a meaningful object, a file is its bytes. Search, query and reasoning read the same data through the read funnel; never build a second copy of the data for them.
- **Work Context:** detours never lose the author's place. Back (browser history), Return to Work (the work stack in `lib/work-place.ts`, per tab and account) and Continue Writing (`work-context` module, the member's writing place) are distinct; don't merge them. Editors of long-form documents pass `workPlace` to the editor. Positions are version-aware and never invented; titles shown for a place come from the server through the read funnel. Work Context is navigation state: never exported, never an undo, never an authorization.
- **Devices and complexity:** desktop, tablet and phone share one architecture and data; only presentation adapts. No Beginner Mode: reveal complexity by context. Genre features are lenses over the common model, never separate genre data models.
- **Decided, not built (see the baseline):** comments are metadata with external anchors, never in the text (87); the Life Planner only sees explicitly shared tasks and events, enforced in data and permissions (88); workspace membership is not access to every project (89). The "Publication status" book field is a temporary compatibility stopgap that nothing new may build on; core character fields are never duplicated as custom fields.
- **Beats and validity** (M14, DECISIONS 112): beats are story objects (`BEAT`, table `beats`) with no Trash of their own (removed through Change Impact or with their structure); placements are `beat_assignments` with a `validity` that the database keeps in step with the scene (`evaluate_beat_assignments` triggers): Potentially Stale while the scene is in the Trash, Conflicted when it leaves the structure's book or series, Intentionally Excepted when the author keeps it (`keepPlacement`), else Current. Never remove, re-place or infer placements; show validity as calm observations. Validity applies to beat assignments only until a later milestone extends it.
- **Tropes** (M13, DECISIONS 110, `tropes` module) are shared story objects (`TROPE`), never owned by a pen name, linked to books, series, relationships and structures only through `uses_trope` connections (no other trope link store). Names are unique among live tropes ignoring case and surrounding spaces; an existing name resolves to the existing trope (no fuzzy matching, aliases or merging). Tropes are author-stated, never inferred. `books.tropes` no longer exists.
- **Dates:** a date that belongs to an object is a calendar entry about it (`calendar.setDeadline`), never a date column on the object.
- **Relationships** have two or more members (`relationship_members`); never assume a pair.
- **Portability:** workspace export, project export, publication export, backup, restore, transfer, migration and cloning are distinct operations over one format. **Exports** are read-only; the JSON export must keep `checkExportIntegrity()` passing when new tables are added.
- **Imports** go through the Import Engine (`imports` module): a source parser produces a Workspace Bundle; validation, plan and the single-transaction apply are shared. A new table needs its bundle schema, validation and plan/apply steps alongside its export. Never write partially.
- **Client components** import other modules only via `ui` entries (services are `server-only`).
- **Server Actions** wrap their body in `runAction()`, return ids instead of calling `redirect()`, and let the client navigate.
- **Auth:** call `requireAuthorContext()` in every page, action and route handler that touches author data. Don't rely on layouts or `proxy.ts` for authorization.
- **Schema:** follow `docs/DATABASE.md` conventions (UUIDv7, snake_case maps, `workspace_id` everywhere, `deleted_at` on creative content). Record notable choices in `docs/DECISIONS.md`.
- **Navigation:** add new sections to `src/config/navigation.ts`.
- **Brand (Brand Specification v1.1, DECISIONS 111):** the product is Spellbound Draft (`src/config/brand.ts`). Colors come from the role tokens in `src/app/globals.css` (light, and dark through `prefers-color-scheme` only: no manual theme switch); never hard-code a color. Type: `font-display` (Cormorant Garamond) for titles 22px and up, Inter for all UI, `font-manuscript` (Literata) for the author's prose. Gold (`accent`) is decorative only. The tagline belongs on the public home page only. The compatibility identifiers `authoros.workspace`, `authoros-drafts`, `authoros-signed-out` and `authoros-json` (and the `authoros:work*` keys) keep the old name on purpose: never rename them; no blind rename of "AuthorOS".
- **Checks before committing:** `pnpm format:check && pnpm lint && pnpm typecheck && pnpm test` (and `pnpm test:e2e` for UI or auth changes).
